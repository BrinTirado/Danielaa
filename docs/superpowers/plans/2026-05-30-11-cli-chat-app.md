# CLI Chat App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the placeholder CLI into a usable terminal interface for Mochi v0.1.

**Architecture:** CLI setup loads config, creates state, memory, fake navigator, action router, prompt builder, and fake LLM by default. The chat session keeps state in memory while memories persist in SQLite.

**Tech Stack:** Typer, Rich, SQLite, pytest, ruff.

### Task 1: CLI Commands

**Files:**

- [x] **Step 1: Write CLI command tests**

```python
from typer.testing import CliRunner

from mochi.cli.main import app


runner = CliRunner()


def test_state_command_shows_location() -> None:
    result = runner.invoke(app, ["state"])
    assert result.exit_code == 0
    assert "living_room" in result.stdout


def test_privacy_commands_toggle_without_crashing() -> None:
    on = runner.invoke(app, ["privacy", "on"])
    off = runner.invoke(app, ["privacy", "off"])
    assert on.exit_code == 0
    assert "enabled" in on.stdout
    assert off.exit_code == 0
    assert "disabled" in off.stdout


def test_chat_exits_cleanly() -> None:
    result = runner.invoke(app, ["chat"], input="where are you?\nexit\n")
    assert result.exit_code == 0
    assert "living_room" in result.stdout
```

- [x] **Step 4: Implement commands**

- `mochi memories`: list memory id, person id, content, importance.
